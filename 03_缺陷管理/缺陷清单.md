## 问题一：用户列表接口对 pageSize 参数缺少边界校验（对应用例 TC_API_005）

| 字段 | 内容 |
|---|---|
| 标题 | 【接口-用户管理】用户列表接口对 pageSize 参数缺少边界校验，异常值（-1/超大值）直接返回数据 |
| 所属模块 | 接口测试 / 用户列表 |
| 测试环境 | RuoYi 本地环境（localhost:81）/ Chrome / Postman |
| 严重级别 | 一般（参数校验缺失 / 接口健壮性不足） |
| 优先级 | 中 |
| 前置条件 | 管理员已登录 |
| 复现步骤 | 1. Postman 调用 `GET /dev-api/system/user/list?pageNum=1&pageSize=-1`；2. 再调用 `?pageNum=1&pageSize=999999`；3. 观察响应状态码与返回内容 |
| 实际结果 | 两种异常参数均返回 **200**，接口不拒绝、不提示参数错误，直接返回数据（未做参数边界校验/限制）。pageSize=999999 返回全量 10 条数据（截图存证） |
| 预期结果 | 对负数/超大 pageSize 应返回参数错误提示，或限制最大分页大小，防止接口被滥用拉取全量数据 |
| 发现方式 | 边界值/异常参数测试（pageSize 取 -1、999999） |
| 价值 | 接口层缺少输入约束：异常参数不报错而是直接返回数据，存在接口滥用与全量数据拉取风险 |

## 问题二：同一账号多浏览器同时登录（会话互斥缺失）

| 字段 | 内容 |
|---|---|
| 标题 | 【登录】同一账号可多浏览器同时登录，无会话互斥机制 |
| 所属模块 | 登录 / 会话管理 |
| 测试环境 | RuoYi 本地环境（localhost:81）/ Microsoft Edge 普通窗口 + 无痕窗口 |
| 严重级别 | 一般（安全策略问题，是否缺陷需产品确认） |
| 优先级 | 中 |
| 前置条件 | 账号 admin 已在普通浏览器窗口登录 |
| 复现步骤 | 1. 普通窗口用 admin/admin123 登录成功；2. 打开无痕窗口用相同账号密码登录成功；3. 观察第一个窗口状态 |
| 实际结果 | 两个窗口均处于登录状态并正常访问用户管理页，旧会话**未被强制下线**（普通窗口 + 无痕窗口同屏截图存证） |
| 预期结果 | 后登录强制下线旧会话（旧 Token 失效，旧浏览器操作跳转登录页）——按单点登录/安全最佳实践预期 |
| 备注 | 是否必须单点登录取决于产品需求，已记录供团队评估，不强行定性为严重 bug |
| 价值 | 会话安全管理策略问题：多端同时在线存在账号共用/越权风险 |
