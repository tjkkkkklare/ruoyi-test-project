## 问题记录（2 个真实问题）

### 1. 用户列表接口对 pageSize 参数缺少边界校验（一般）

- 操作：`GET /dev-api/system/user/list?pageNum=1&pageSize=-1` 与 `?pageNum=1&pageSize=999999`
- 实际：均返回 200，接口不拒绝、不提示参数错误，直接返回数据（999999 时返回全量数据）
- 预期：对负数/超大 pageSize 应返回参数错误提示，或限制最大分页大小
- 风险：接口层缺少输入约束，存在接口滥用与全量数据拉取风险
- 证据：`evidence/` 目录 Postman 复现截图

### 2. 同一账号多浏览器同时登录，无会话互斥（一般）

- 操作：普通窗口登录 admin 后，无痕窗口使用相同账号登录
- 实际：两个窗口均在线并正常访问，旧会话未被强制下线
- 预期：按单点登录/安全最佳实践，后登录应强制下线旧会话
- 备注：是否必须单点登录取决于产品需求，记录为"待产品确认"
- 证据：`evidence/` 目录双窗口同屏截图

## 后续改进建议

1. 接口层增加参数边界校验（如限制 pageSize 最大值）
2. 全局异常统一处理，不向前端返回堆栈信息
3. 会话策略与产品对齐（明确单点登录或多端在线策略）
4. 用例设计前先确认需求口径，避免预期假设与产品实现不符
5. 后续补充自动化回归（Postman Runner / Selenium）
